System Design Interview Framework

Universal pattern — works for any system design question

Mental Trigger — Say This First
Clarify → Scope → HLD → Deep Dive → Scale & Trade-offs
1
Clarify Requirements
2–3 mins
Never jump to solution. Ask these first — every time.
Functional
What are the core features we must build? (not nice-to-have)
Who are the users? (consumers, enterprises, internal teams)
What does the main user flow look like end to end?
Non-Functional
What is the expected scale? (DAU, requests/sec, data volume)
Is this read-heavy or write-heavy?
What is the latency requirement? (real-time, near-real-time, batch)
Any availability/consistency requirements? (99.9% uptime?)
Any geographic constraints? (single region or global?)
2
Define Scope
1–2 mins
Say out loud what you will and won't cover. Shows structured thinking.
Say: "I'll focus on X, Y, Z and skip A, B for now"
Estimate scale: DAU × requests/user = total RPS. Say the number.
Estimate storage: data size × users × retention. Say the number.
Confirm: "Does this scope align with what you're looking for?"
3
High Level Design (HLD)
5–8 mins
Draw boxes and arrows. Keep it simple — 5 to 7 components max.
Always include these boxes
Client → (web/mobile/API consumer)
API Gateway / Load Balancer → entry point
Core Service(s) → main business logic
Database(s) → primary storage
Cache → if read-heavy (Redis)
Queue → if async processing needed (Kafka, SQS)
Storage → if files/blobs (S3)
Questions to ask yourself while drawing
Where does data enter the system?
Where does data get stored?
Where does processing happen?
Where does data exit to the user?
4
Deep Dive (2–3 Components)
8–10 mins
Pick the hardest parts. Don't try to explain everything.
How to pick what to deep dive
What is the most complex part of this system?
What is the biggest bottleneck at scale?
What part is unique to this problem vs generic CRUD?
Questions to answer in each deep dive
What is the data model / schema?
What are the APIs for this component?
Why did I choose this DB / this approach?
What happens on failure? (retry, fallback, dead letter queue)
How does consistency work here?
5
Scale & Trade-offs
3–5 mins
This is where senior candidates separate from juniors. Always end here.
Scale questions to address
If traffic 10x, what breaks first and how do I fix it?
Where do I add horizontal scaling? (stateless services)
Where do I add caching? (read replicas, Redis, CDN)
Where do I shard the database? What's the shard key?
Do I need a CDN? (static assets, geo-distributed users)
Trade-off questions to address
Why SQL vs NoSQL? (structured + ACID vs flexible + scale)
Why sync vs async? (latency vs reliability)
Why monolith vs microservices? (simplicity vs scale)
What did I sacrifice? (consistency, cost, complexity)

⚡ Golden Rules

1. Always clarify before drawing anything. Jumping = red flag.
2. Think out loud. Interviewers want to hear your reasoning, not just the answer.
3. Say "I'd choose X because Y, but the trade-off is Z" — not just "I'd use Redis."
4. You don't need a perfect design. You need a defensible one.
5. If stuck, go back to requirements. The answer is usually there.
Practice daily with 1 question. Use VidyaTrack or CitiusTech RAG as your first example.
